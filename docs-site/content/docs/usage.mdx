# 用法

**本页回答**：这个插件怎么装进一个 home、要配哪些设置、agent 与人分别从哪儿操作它、怎么确认备份真的在转。

## 装进 home

```powershell
# 进 home（一个普通的 npm 项目根）
pnpm add @godcreator/gwb-windows-backup@<版本> @cordisjs/plugin-timer
```

`cordis.yml` 手写两条条目：`id: windows-backup` 与 timer 条目（name
`@cordisjs/plugin-timer`）。**timer 条目缺了本插件整个挂起等它**——顶层 `inject` 是等待语义，
宁挂起，不静默不备份。

{/* ref file="../src/index.ts" lines="90-90" */}

数据目录由数据插件按条目 id 给出（`<home>/data/windows-backup`），全部用户数据住那里。
装完 restic 本体放进 `bin/restic.exe`（或用 `restic-exe` 设置指向别的位置）——装 restic
是一次性手工活，代码不代办。

## 设置（15 键，kebab-case）

设置经 gwb-settings 声明，**每次跑现读现用、绝不缓存**——设置插件没有变更通知，缓存一份
就会「设置改了、跑的还是旧值」。类型不对或缺字段的值吃默认，不报错。

{/* ref file="../src/index.ts" lines="93-115" */}

必填两项：`sources`（分号分隔的备份白名单）与 `local-repo`（本地 restic 仓库路径）。
缺任何一项，定时那轮照转但每轮都拒跑，拒跑理由是一句指路的话。

{/* ref file="../src/backup.ts" lines="114-130" */}

OSS 三项（`oss-bucket` / `oss-endpoint` / `oss-repo-path`）只在 `oss-enabled` 开着时才被
要求；凭据不进设置——`credentials/oss-credentials.txt`（KEY=VALUE，支持 `export ` 前缀、
引号、`#` 注释）。仓库密码放 `credentials/restic-password.txt`，内容任何时刻都不进本进程。

## 命令（六条，MCP 插件自动开给 agent）

{/* ref file="../src/index.ts" lines="432-552" */}

| 命令 | 干什么 |
| --- | --- |
| `windows-backup.run` | 立刻跑一轮完整备份（= 定时那轮干的事）；占不到锁、配置没填全会如实说 |
| `windows-backup.check` | 立刻跑一次五项健康检查，回全量状态 |
| `windows-backup.status` | 回全量状态（上次备份、自检结论、定时器节奏）——窗格轮的就是它 |
| `windows-backup.paths` | 回数据目录全部路径——看凭据在不在、tail 日志，先调这条拿路径，别猜 |
| `windows-backup.restic` | 透传一条 restic 命令（如 `{ "repo": "local", "args": ["snapshots"] }`），自动补 `--repo` 与 `--password-file`，密钥不出现在参数里。恢复快照也走它：`args: ["restore", <id>, "--target", <目录>]` |
| `windows-backup.mark` | 补记周期动作时间戳：`{ "what": "usb-copy" \| "exclude-audit", "at": "YYYY-MM-DD" }` |

## 怎么确认备份在转

1. `windows-backup.status`：`backup.lastRunOk` 是 `true`、`nextRunAt` 在未来；
2. `windows-backup.check`：五项没有 problem；
3. 有疑问直接看日志（`windows-backup.paths` 拿路径）：最后一轮末尾应有
   `Backup completed successfully`。

挂载后 30 秒是第一轮：先自检，上一轮备份太旧（超过一个周期）就顺带补跑一轮。不在挂载
当场跑——挂载期整棵树都在起，起 restic 等于拿仓库 I/O 堵启动。

{/* ref file="../src/index.ts" lines="554-571" */}

**宿主不在就不备份**——定时器住在 gwb 工作台里，工作台关了备份就停，下次起来 30 秒后
补。这是知情认下的代价；要机器级保底，等 roadmap 上的灾难 CLI 入口。
