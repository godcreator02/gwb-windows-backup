`src/credentials.ts` 把运行时凭据交给 gwb-settings 的 secret 槽。普通配置走 `settings.*`，凭据状态与导入走 `credentials.*`；`windows-backup.paths` 返回键名与旧恢复文件位置，不返回原文。

| 凭据键 | 内容 | 子进程使用方式 |
| --- | --- | --- |
| `restic-password` | 当前仓库实际使用的密码 | `RESTIC_PASSWORD` 环境变量 |
| `oss-credentials` | KEY=VALUE 文本，必需 `AWS_ACCESS_KEY_ID`、`AWS_SECRET_ACCESS_KEY`，可选 `AWS_SESSION_TOKEN` | 只在 OSS 调用中解析并注入 |

## 原值迁移

首次加载逐项复制旧 `credentials/restic-password.txt` 与 `oss-credentials.txt`。Restic 文件按 restic v0.18.1 的规则去除 BOM、识别 UTF-8/UTF-16、去除 Unicode 首尾空白；中间换行保留。依据是 [restic 密码读取实现](https://github.com/restic/restic/blob/v0.18.1/cmd/restic/global.go) 与 [文本解码实现](https://github.com/restic/restic/blob/v0.18.1/internal/textfile/read.go)。无法无损解码时停止该项迁移，保留原文件。

已有 home 凭据优先；成功后记录迁移标记。标记存在时，删除新库里的值会保持删除，旧文件不会恢复它。写入失败不删除旧文件，修复后重新加载插件再试。OSS 迁移失败仍允许本地备份，OSS 阶段记失败。

旧文件保留作恢复材料，修改它们不会改变运行时凭据。更换凭据用 `credentials.import/copy` 或设置界面；不要为现有仓库生成新密码。不同 home 没有自动借用关系。

## 进程与回执

父进程环境先移除 AWS、RESTIC、MINIO 认证来源，禁用实例元数据和用户级 AWS 文件，再注入当前 home 的凭据。父进程环境不修改。透传参数不能覆盖仓库、密码文件或密码命令。

Restic 的 stdout/stderr 在交给日志与命令回执前遮掉本次注入的凭据。异常只返回操作阶段与配置键；不把凭据文本拼进错误。

## 恢复之前必须备到什么

白名单应包含 home 的 `settings.json`、`credentials.json`、`cordis.yml`、`package.json`、锁文件、workspace 配置，以及 `data/`；home 有 `.npmrc` 时也覆盖它。`paths.homeRecoveryFiles` 给出候选路径，只添加实际存在的文件。插件不会静默扩大白名单。排除规则不得误伤凭据库与旧恢复文件。

另保存一份可独立取得的仓库密码与必要 OSS 凭据到离机恢复介质。只有加密快照里的密码，无法解锁这个快照本身。恢复时先用离机材料解锁仓库，再恢复匹配的 home 插件清单、普通设置、凭据库和数据；不要只恢复其中一个文件。

`tests/home-credentials.test.ts` 覆盖编码、原值、写入失败、删除后重载、home 隔离、继承环境和回显遮挡。真实账号不用于自动测试。
