`src/credentials.ts`。纪律一句话：**凭据永不进设置、永不进日志、永不进报错消息**。十六个设置键里没有一个是密钥。

## 两份凭据，两种待遇

| 文件（数据目录的 `credentials/` 下） | 待遇 |
| --- | --- |
| `restic-password.txt` | 内容**永不读进本进程**，只把路径交给 restic 的 `--password-file`。读进内存，就有机会被某条日志或某个报错带出去 |
| `oss-credentials.txt` | 非读不可（restic 写 `s3:` 仓库从环境变量取 AccessKey），解析结果只进那一次子进程的环境变量 |

## OSS 凭据文件的格式

每行 `KEY=VALUE`，值原样取到行尾；空行与 `#` 开头的行跳过。必须有 `AWS_ACCESS_KEY_ID` 与 `AWS_SECRET_ACCESS_KEY` 两个键：

**格式不对就报错**：某一行不是 `KEY=VALUE`、缺了必需的键、文件不在，都抛错。报错里只有文件路径、第几行、缺哪个键——
**不带任何一行的内容**，那会把凭据带进日志。

用到它的只有两处，都是「塞进子进程环境变量」这一条路：

- [一轮备份](/docs/windows-backup/round)的 OSS 那次：读不出就把 OSS 那次记成失败，日志里写一行 `OSS push FAILED: <原因>`，不启动 restic；本地那次照常算
- `windows-backup.restic` 透传 `repo: "oss"` 的那一次：读不出就在回执里报错，不启动 restic

环境变量是 `resticEnv` 造的副本，父进程的环境从头到尾不改，本进程之后启动的任何子进程都不会带着 OSS 密钥
（见 [restic 与子进程](/docs/windows-backup/restic#环境变量)）。
