# 配置与状态

**本页回答**：15 个设置键怎么变成程序里的嵌套配置、坏值为什么吃默认、`state.json` 记了哪些时间戳与哪两份快照 ID。

`src/config.ts` + `src/state.ts` + `src/timers.ts`。

## 管什么

`config.ts` 管两个形状和中间那座桥：**平铺形状 `FlatConfig`**（15 键，
`sources` 是分号分隔的一个串——单值文本框装数组最自然的写法）与**嵌套形状 `BackupConfig`**
（程序内部真正在用的，`sources` 是数组）。设置插件只收 kebab-case，宿主层有一张对照表负责
换名，两个键名世界不相认。

**不知道什么**：不知道设置界面上长什么样；不知道 `state.json` 里除了自己写的键还有什么。

## 坏值吃默认

设置插件没有校验钩子，谁都能往键里写东西，读这一头就是全仓唯一的守门员：缺字段、类型
不对一律吃默认；频率 / 自检间隔另有「非正数退回默认」——写 0 进去等于让定时器每 0 毫秒
疯转，退回默认比照收安全。留空的那几项（`sources` / `localRepo` / `ossBucket` /
`ossEndpoint`）是「逐字段问用户」的字段，塞一个像模像样的假默认只会让人以为配好了。

分号串切成路径数组时**去空白、去空项**——用户多打一个分号是常态，切出来的空项要是原样
进 `restic backup` 的 argv，restic 会去备份「当前目录」。

日志轮转的两个数字（10 MB / 1000 行）**不在设置表上**——它不是用户该操心的旋钮，改它的
人是在改代码不是在改配置。

## state.json：动作时间戳与两份父快照 ID

{/* ref file="../src/state.ts" lines="15-47" */}

不靠 mtime 判跨日（空文件那类存法）：mtime 这种「载重信息在元数据里」的存法，任何一次拷贝 /
同步 / 解压都可能把它抹平，症状是 prune 每次都跑或永远不跑。**fail-safe**：解析失败当空
对象——这份文件坏掉最坏的后果是多跑一次 prune，为它中断整条备份链路不划算。

时间戳一律本地时区、无时区标记（`YYYY-MM-DDTHH:MM:SS`）：「跨日」是人过的那个日子，
不是 UTC 的；无标记的串被 `new Date` 按本地时间解析，写读两头口径对得上。

另有两格不是时间戳：`lastLocalSnapshot` / `lastOssSnapshot`——最近一次成功备份留在两个仓里
的快照 ID，下一轮交给 restic 的 `--parent` 当基准。为什么非记不可，见[备份管线](/docs/modules/pipeline)。

## 提供的接口

| 接口 | 干什么 |
| --- | --- |
| `pickFlat` / `flatToConfig` | 来路不明的值 → 平铺表 → 嵌套配置 |
| `splitSources` | 分号串 → 干净的路径数组 |
| `resolveSlotPath` | 路径类字段按数据目录解析（绝对原样、`~/` 展家目录、其余按数据目录拼） |
| `readState` / `writeState` | merge 写，只动 patch 里的键 |
| `shouldRunPrune` / `shouldCatchUp` / `intervalMsOf` / `backupIntervalMsOf` | `timers.ts` 的三个纯函数：每日一次的旗子、起来补跑的判据、周期换算（不合法退回默认，不悄悄夹到边界） |

## 依赖的接口

只依赖 node 内建 `os` / `path` / `fs`。无注入点，纯函数配上临时目录就能测。

## 怎么单独测

`tests/config.test.ts`、`tests/state.test.ts`、`tests/timers.test.ts`：喂坏值证明吃默认、
喂分号串证明去空项、喂时间戳证明跨日与分钟差的口径。
