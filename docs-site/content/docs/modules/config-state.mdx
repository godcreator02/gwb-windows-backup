**本页回答**：17 个设置键怎么变成程序里用的配置、坏值为什么用默认值、`state.json` 记了什么、定时器的周期怎么换算。

`src/config.ts` + `src/state.ts` + `src/timers.ts`，都是只看输入输出的纯函数，配上临时目录就能测。

## 两个形状

设置插件里的键是 kebab-case（`frequency-minutes`），宿主层 `SETTING_KEYS` 那张表把它们换成平铺形状 `FlatConfig` 的 camelCase 字段；
`flatToConfig` 再把平铺形状收成程序内部用的嵌套形状 `BackupConfig`（`restic`、`repositories.local` / `oss`、`schedule`、`retention`……）。
日志轮转的两个数字（10 MB、1000 行）只在嵌套形状里，不上设置表：它不是用户该调的旋钮。

## 坏值用默认值

设置插件不校验写进来的值，读这一头是唯一把关的地方：缺字段、类型不对一律用默认值；频率、自检间隔、保留份数这类数字不是正数也用默认值——
写 0 进频率等于让定时器每 0 毫秒触发一次，退回默认比照收安全，而且**退回默认、不夹到边界**。

默认值里有几项故意留空：`sources`、`local-repo`、`oss-bucket`、`oss-endpoint` 要用户逐项给，塞一个像模像样的假默认只会让人以为配好了。
`oss-enabled` 默认关：新机器只配了本地仓库就开始备份时，不会每一轮多一次注定失败的 OSS 备份、通知天天报 partial。

白名单分号分隔的一整串也认（旧版设置里是这个写法）：切开时去掉空白与空项——用户多打一个分号是常有的事，切出来的空项要是原样进了
`restic backup` 的参数，restic 会去备份「当前目录」。

路径类设置（`restic-exe`）按数据目录解析：绝对路径原样，`~` / `~/` 展开成家目录，其余拼在数据目录后面。

## state.json

{/* ref file="../plugins/windows-backup/src/state.ts" lines="4-23" hash="0664142270f3" blob="e08a9dbb2092" */}

时间一律本地时区、不带时区标记（`YYYY-MM-DDTHH:MM:SS`）：「跨日」按人过的日子算；不带标记的串被 `new Date` 按本地时间解析，写与读两头对得上。
不靠文件修改时间判跨日：修改时间放在元数据里，任何一次拷贝、同步、解压都可能把它抹平，症状是 prune 每次都跑或永远不跑。

写是合并写，只改这次给的字段。读不了（文件不在、JSON 坏了、不是对象）就当空对象：这份文件坏了最坏多跑一次 prune，为它中断整条备份不值得。
两份快照 ID 为什么非记不可，见[备份管线](/docs/modules/pipeline#父快照)。

## 周期换算

`timers.ts` 三个函数：自检间隔小时换毫秒、备份周期分钟换毫秒（不合法就退回 `DEFAULT_FLAT` 里的默认值，默认值不在第二处写死）；
`shouldCatchUp` 判加载 30 秒后要不要补跑：从没跑过，或上一轮离现在已满一个周期。
