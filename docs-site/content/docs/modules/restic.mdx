# restic 封装与子进程

**本页回答**：restic 的命令行怎么拼、retention 与 OSS 仓库 URL 为什么只有一处定义、起子进程有哪几条不许绕的规矩。

`src/restic.ts` + `src/process.ts`。参数跟 restic 的实际接受度绑死，重拼一次就是重踩一次坑。

## 管什么

`runRestic` 补 `--repo` 与 `--password-file`，调用方只给子命令与参数；`ossRepoUrl` 拼
`s3:<endpoint>/<bucket>/<repoPath>`；`pruneArgs` 拼 forget 的保留窗口参数。**不知道什么**：
不知道仓库里有什么、不知道密码内容（路径过手，内容不读）。

两串参数是 SSOT：透传命令（`windows-backup.restic`）、全流程备份、健康检查的快照项都从
这两个函数取，改 retention 字段只改一处。

保留窗口的默认口径：72 小时内全留、按日留 14 天、周 8 份、月 12 份（`DEFAULT_FLAT`，
可在设置里改）。

超时分两档：restic 备份 / prune 给 6 小时（首次全量几十 GB 是常态），其余子进程（快照
查询、toast）默认 2 分钟。退出码约定：信号杀掉记 `-1`、起不来记 `-2`——都是非零，调用方
按失败处理即可。异常转人话只取 `message` 不带栈，**栈里可能夹着命令行参数**。

## env 的边界

`resticEnv` 造的是**这一次子进程专用的一份副本**：父进程 env 打底、叠 `GOMAXPROCS`，
OSS 那趟再叠 AccessKey 两键——父进程的 env 从头到尾没碰过，本进程后续起的任何子进程都
不会带着 OSS 密钥。

## 提供的接口

| 接口 | 干什么 |
| --- | --- |
| `runRestic(exe, repo, args, opts)` | 补全全局参数后真跑一条 restic 命令 |
| `ossRepoUrl` / `pruneArgs` | 上面说的两处 SSOT |
| `parseSnapshotId` / `parseProcessedSize` | 从成功 stdout 里抠 `snapshot abc12345 saved` 与 `processed N files, X GiB` |
| `runProcess(exe, args, opts)` | 裸的子进程执行，返回 `{ code, stdout, stderr, timedOut }` |

## 依赖的接口

只依赖 node 内建 `child_process`。`run` 参数与 `RunProcess` 类型是全部注入点。

## 怎么单独测

`tests/restic-credentials.test.ts`：注入假 `run`，证明全局参数的顺序与位置、OSS URL 与
prune 参数的拼法、env 副本不污染父进程、两个解析函数对真 restic 输出样例的识别。
