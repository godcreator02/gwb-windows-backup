**本页回答**：restic 的命令行怎么拼、保留窗口与 OSS 仓库地址为什么各只有一处拼法、启动子进程有哪几条规矩、环境变量里的密钥为什么不会漏到别的子进程。

`src/restic.ts` 管 restic 的参数，`src/process.ts` 管启动进程。restic 的密码内容这里不读，只传密码文件的路径；仓库里有什么也不关心。

## 参数只有一处拼法

`runRestic` 在调用方给的子命令前补上 `--repo <仓> --password-file <路径>`。OSS 仓库地址 `s3:<endpoint>/<bucket>/<repoPath>` 与
forget 的保留窗口参数各只有一个函数拼：透传命令、备份管线、五项自检都从这里取，改保留窗口只改一处。这两串参数跟 restic 实际接受的写法绑在一起，
另拼一份就可能再撞一次已经解决过的参数问题。

保留窗口默认：72 小时内全留、按日留 14 天、按周留 8 份、按月留 12 份（设置里可改）。forget 按主机分组（`--group-by host`），不用 restic
默认的主机加路径：按默认分组，白名单每改一次就多出一组，每组各自留满保留窗口，旧组永远删不掉（轨迹卡[prune 按主机分组](/trajectory/2026-09-25-prune-group-by-host)）。

## 子进程四条规矩

`src/process.ts` 的 `runProcess` 是全插件唯一启动外部程序的地方，一条都不许绕：

- **argv 数组、不经 shell**：备份的参数里有用户给的路径，经 shell 就等于把 `&` `|` `^` 交给命令解释器
- **每次都带超时**：定时器每 30 分钟启动一轮，一个卡住的 restic 会在后台越积越多，直到内存用光
- **`windowsHide: true`**：定时跑起来不弹黑框
- **不抛**：启动不了、超时都收进 `{ code, stdout, stderr, timedOut }`，由调用方按业务判——日志里那行
  `FAILED with exit code N` 比异常栈有用

{/* ref file="../plugins/windows-backup/src/process.ts" lines="33-62" hash="0b58cf974c9d" blob="2d764c3a1ba7" */}

超时分档：restic 备份与 prune 6 小时（第一次整份备份几十 GB 是常态），其余（查快照、弹通知）默认 2 分钟、通知 10 秒。退出码约定：
被信号杀掉记 `-1`、启动不了记 `-2`，都是非零，调用方按失败处理。异常只取 `message` 不带栈：**栈里可能带着命令行参数**。

## 环境变量的边界

`resticEnv` 造的是**这一次子进程专用的副本**：父进程环境打底，叠上 `GOMAXPROCS`，OSS 那几次再叠 AccessKey。父进程的环境从头到尾不改，
本进程之后启动的任何子进程都不会带着 OSS 密钥。

{/* ref file="../plugins/windows-backup/src/restic.ts" lines="49-56" hash="1de38a8e9baa" blob="45169cb2b3f0" */}

备份成功时，从 restic 的输出里取两样：`snapshot abc12345 saved` 里的快照 ID（下一轮的父快照）与 `processed N files, X GiB` 里的体量（通知正文）。

## 测试

`tests/restic-credentials.test.ts` 注入假的启动函数，查全局参数的顺序与位置、OSS 地址与保留窗口参数一字不差、环境变量副本不改父进程、
两个解析函数对真实 restic 输出样例的识别。
