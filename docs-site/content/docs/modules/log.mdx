# 日志契约与通知

**本页回答**：备份日志里哪些行是机器读的契约、失败关键词怎么收窄、结束通知从哪儿出去。

`src/log.ts` + `src/messages.ts` + `src/toast.ts`。

## 管什么

`log.ts` 管往 `<数据目录>/logs/restic-backup.log` 写：`[YYYY-MM-DD HH:MM:SS] <msg>` 一行
一条，子进程输出原样附上（不加时间戳——restic 自己的排版有信息量），超 10 MB 只留末
1000 行。一律同步写：链路上一条日志没落盘就崩了，等于没有排查线索。

`messages.ts` 是契约行的**唯一出处**。写日志的一头（备份管线）和读日志的一头（五项健康、
将来手册的验收步骤）必须认同一串字；让两头各自写字面量，迟早改了一头忘了另一头，症状是
「健康检查报一切正常，其实备份三个月前就断了」。

{/* ref file="../src/messages.ts" lines="12-17" */}

英文不是随手写的：这几串字是**既有契约**——用户的存量日志里躺着的就是它们，翻成中文
等于把存量日志作废。改一个词，健康检查就会把「备份早就断了」读成
「一切正常」，而这种误报要等到灾后取数据那天才现形。

## 失败关键词的收窄

五项健康的第②项在日志尾搜四个词：`FAILED` / `Fatal` / `exit code` 出现即算数；
`error` 单拎出来收窄两道——整词匹配、先扣掉 `0 errors` 计数行。判据还是那句：**误报比
漏报更伤**。

## toast 通知

`toast.ts` 走 Windows PowerShell 5.1 + WinRT 弹系统通知（`powershell` 而不是 `pwsh`——
任何 Windows 都有前者）。成败都通知，不做「宿主在就不弹」的判断：无人值守的机器上，
toast 与窗格是两条互补的观察面。

转义是唯一的技术难点，两层嵌着：XML 文本进的是 PowerShell 单引号字面串，所以 `'` 与 `"`
都得转成 XML 实体——stdlib 那种「只管 `& < >`」的转义在这儿不够。

{/* ref file="../src/toast.ts" lines="4-9" */}

弹失败只记一行 `Notification failed: ...`、不抛——通知弹不出来不该把已经跑完的备份判成失败。

## 提供的接口

| 接口 | 干什么 |
| --- | --- |
| `createLogger(file)` | 造 logger：`line`（带时间戳）/ `raw`（原样）/ `rotate`（超阈值留末 N 行） |
| `nullLogger()` | 什么都不写的 logger，测试与「只算不写」用 |
| `messages.ts` 的常量与拼行函数 | 全部契约行；别处一律引用，不写字面量 |
| `matchesFailure(line)` | 一行算不算失败迹象 |
| `sendToast(title, body)` | 弹通知；失败只记日志 |

## 怎么单独测

`tests/log-toast.test.ts` 与 `tests/messages.test.ts`：临时目录里证明轮转留行数、契约行拼法
逐字对、`matchesFailure` 对 `0 errors` / 整词边界的判定、XML 转义对单双引号的处理。
