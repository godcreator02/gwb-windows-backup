**本页回答**：备份日志里哪些行是给程序读的契约、失败关键词怎么收窄、结束通知怎么弹出来。

## 日志

`src/log.ts` 往数据目录的 `logs/restic-backup.log` 写：`[YYYY-MM-DD HH:MM:SS] <内容>` 一行一条，restic 的输出原样附上
（不加时间戳，restic 自己的排版有信息量），超过 10 MB 只留最后 1000 行。一律同步写：链路中途崩了，已经写的行都在盘上。

## 契约行

`src/messages.ts` 是契约行的唯一出处。写日志的一头（备份管线）与读日志的一头（五项自检的第②项，将来手册里的验收步骤）必须认同一串字；
两头各写各的字面量，迟早改了一头忘了另一头，症状是「自检说一切正常，其实备份三个月前就断了」。

四组：`Backup`、`Prune`、`OSS push`、`OSS prune`，每组 `started` / `completed successfully` / `FAILED with exit code N`；另有
`Log rotated (kept last N lines)` 与 `Notification failed: <原因>`。英文是存量日志里已有的写法，翻成中文等于让存量日志作废；
改一个词，自检就会把断掉的备份读成正常，而这种误报要到灾后取数据那天才发现。

## 失败关键词

第②项在日志尾搜四个词：`FAILED`、`Fatal`、`exit code` 出现即算；`error` 收窄两道——整词匹配（不然 `terror` 也算），先扣掉 `0 errors`
这种计数行（restic 每轮正常输出里都有）。判据还是那句：误报比漏报更伤。

{/* ref file="../plugins/windows-backup/src/messages.ts" lines="53-58" hash="37ec501f659e" blob="dd618ded29f8" */}

**有一行刻意不含这四个词**：父快照失效、要不带父快照重跑时补的说明行（`parentDroppedLine`）。它不是失败，是自我修复的第一步；
写成失败关键词，第②项会把一次正常的重跑记成故障。配套的 `parentUnusable` 只认 restic 说「父快照找不到」的那两句原话，别的失败一个都不重试。

## 结束通知

`src/toast.ts` 用 Windows PowerShell 5.1 调 WinRT 弹系统通知，用 `powershell` 不用 `pwsh`：任何 Windows 都有前者。成败都通知，
不判断「工作台开着就不弹」：没人看屏幕的机器上，通知与窗格互补，谁也替代不了谁。

转义是唯一的难点，嵌了两层：XML 文本要放进 PowerShell 的单引号字符串，所以 `'` 与 `"` 也要转成 XML 实体，只转 `& < >` 不够。

{/* ref file="../plugins/windows-backup/src/toast.ts" lines="10-21" hash="a65cb9ece723" blob="376e07f1e708" */}

弹失败只记一行 `Notification failed: ...`，不抛：通知弹不出来，不该把已经跑完的备份判成失败。设置键 `toast` 关掉就整个不弹。

## 测试

`tests/log-toast.test.ts` 与 `tests/messages.test.ts`：临时目录里查轮转留的行数、契约行逐字对得上、`matchesFailure` 对 `0 errors` 与整词边界的判定、
XML 转义对单双引号的处理、弹失败只记一行。
