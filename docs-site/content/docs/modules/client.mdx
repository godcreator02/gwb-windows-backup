# 备份窗格

**本页回答**：窗格从哪儿拿数据、轮询停不停跟着什么走、灰灯为什么不是「没问题」。

`src/client/`。浏览器侧代码，esbuild 打包；react 的四个包名不打包，由页面的 importmap 解析到内核包
`@godcreator/gwb-kernel-desktop` 提供的那一份，各插件共用同一个实例。外壳先加载本插件的 `style.css`
再 `import` 这份模块——样式表的类名全带本插件的前缀，只作用于本插件自己的元素。

## 管什么

一个窗格（`mountPane`，id `main`）：状态灯与一句话、上次备份一行、两个按钮（立即备份 /
立即检查）、五项自检逐项、数据目录一行。**不知道什么**：不知道备份在 node 侧怎么跑——
它只会调 `windows-backup.status` / `run` / `check` 三条命令；node 侧的定时器（备份与自检
本体）跟这边毫无关系，**界面不在备份照跑**。

注册时不给 `kind`，外壳按**工具窗格**处理（shell 0.13 起整页至多一份）：别的桌面上已经开着，
再打开就是切到那张桌面激活它、不开第二份——人在「新建」里点的会切过去，插件与命令打开的不切、
状态栏提示一句。本插件自己不调打开窗格的命令，这条对代码没有要求。

## 挂载契约

外壳调 `mountPane` 时给 `host`（调命令的接口）与 `pane`（窗格身份）；契约要求**同步**返回
`{ dispose }`——返回 promise 或返回函数都算违约。未知窗格 id 显示一行错误而不是白屏。

## 轮询跟挂载走

取数走 `host.call('windows-backup.status')`，30 秒一轮；窗格被关掉时 `dispose` 清掉
定时器。调命令失败不会让窗格崩掉：连接断了窗格还在，留着上一次的结论，下一轮轮询自然带回最新状态。

## 灰灯的口径

`report === null` 是「还没有结论」（挂载 30 秒后的第一次自检还没跑），**不是「没问题」**——
据此画灰灯；五项里的 `unknown` / `skipped` 同理画灰不画红。颜色只表示状态，「正在跑」
用灯的呼吸动画表示，不改变颜色。

## 提供的接口

对外壳导出 `mountPane`。`view.ts` 把 `status` 的回执收窄成界面要用的形状、决定怎么显示（形状的正本在
node 侧 `snapshot()`，这边只收窄用得上的字段，不照抄全部字段）。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `host.call` | 三条命令 | 外壳给的调命令接口 | 无 |
| react / react-dom | 渲染 | 页面 importmap，内核包提供 | 构建时不打包 |

## 怎么单独测

`tests/plugin.test.ts` 用假的外壳测了「外壳在场就注册窗格、不在场备份照常」，不查窗格 id 与报给外壳的
client/style 地址；`view.ts` 的
收窄与 `toneOf` 是纯函数，不开页面就能测，目前没有专门的测试。浏览器侧不开真页面，
类型检查用单独一份 tsconfig。
