**本页回答**：窗格从哪儿拿数据、轮询什么时候停、灰灯为什么不等于「没问题」。

`src/client/`，浏览器侧代码，esbuild 打包。窗格只会调 `windows-backup.status` / `run` / `check` 三条命令，不知道备份在 node 侧怎么跑；
备份与自检的定时器在 node 侧，跟窗格无关，**界面不在，备份照跑**。窗格和外壳、命令总线之间的连接见首页[接缝 5–7](/docs#接缝逐条)。

注册时不写 `kind`，外壳按工具窗格处理：整页至多一份，别的桌面上已经开着就切过去激活它。本插件自己不打开窗格。

## 挂载

外壳调 `mountPane` 时给 `host`（调命令的接口）与 `pane`（窗格身份）；必须**同步**返回 `{ dispose }`。认不出的窗格 id 显示一行说明，不留白屏。

## 轮询跟着挂载走

`useStatus` 挂载时取一次、之后每 30 秒取一次，卸载时停。调命令失败时窗格不清空，留着上一次的结论，下一轮轮询再取。

## 灰灯不是「没问题」

`report === null` 是「还没有结论」（加载 30 秒后的第一次自检还没跑），画灰灯；五项里的 `unknown` / `skipped` 同样画灰不画黄。
颜色只表示结论，「正在跑」只加呼吸动画，不改颜色。

`view.ts` 把 `status` 的回执收窄成界面要用的形状：形状的正本在 node 侧的 `snapshot()`，这边只收用得上的字段，认不出的给默认值。

## 复核横幅

周期维护里的「人工复核」到期时，窗格顶上显示一条横幅，按钮把一段复核提示词复制进剪贴板：贴给任何能调命令的 agent，照着走一遍——
跑一次自检、看状态、用透传命令核对最近的快照——就是一次人工复核；复核完调 `windows-backup.mark {"what":"review"}` 记下日期，横幅消失。

## 样式

类名一律带 `windowsbackup:` 前缀，样式只作用于本插件画出来的元素；颜色只用外壳的主题令牌，加一个本插件的成功色（`tokens.css`，
亮暗各一套），呼吸动画是样式入口 `@theme` 里的 `animate-breathe`。这些由 `devkit.dev` / `devkit.release` 的样式检查查。

三个按钮都是 shadcn 官方的 `Button`：`src/client/components/ui/` 下的组件文件由 `pnpm dlx shadcn@latest add` 在插件包目录生成
（配置在包根 `components.json`，`@/` 别名在包根 `tsconfig.json`、`src/client/tsconfig.json`、`build.ts` 三处都指向 `src/client`），
不手改样式。使用处只选 `variant` 与 `size`：「立即备份」是缺省变体，「立即检查」和横幅里的「复制复核提示词」是 `outline`。
官方变体里没有警告色，警告色只在横幅的底色、边框与文字上。组件用到的 `radix-ui`、`class-variance-authority`、`cn`
写在 dev 依赖里，打包进 `client.js`。

## 测试

浏览器侧没有测试，类型检查用单独一份 `src/client/tsconfig.json`（只带 DOM 类型）。`tests/plugin.test.ts` 查外壳在与不在两种情况都能加载；
`tests/artifact.test.ts` 查构建出的 `client.js` 里有 `mountPane` 与它轮询的命令名。先读 `BackupPane.tsx`，再读 `view.ts` 与 `hooks.tsx`。
