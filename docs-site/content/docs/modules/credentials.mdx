# 凭据纪律

**本页回答**：仓库密码与 OSS AccessKey 各自走什么路进 restic、为什么解析失败的行不报错。

`src/credentials.ts`。纪律一句话：**只算路径、只解析 KEY=VALUE，不往日志 / stdout / 异常
消息里漏一个字节**。凭据也**永不进设置**——设置面 15 键里没有一个键是密钥。

## 管什么

两份凭据，待遇刻意不一样：

| 文件 | 待遇 |
| --- | --- |
| `credentials/restic-password.txt` | 内容**永不进本进程**，只把路径交给 restic 的 `--password-file`。读进内存就有机会被某条 `console.log` 或某个异常的 `error.message` 带出去 |
| `credentials/oss-credentials.txt` | 非读不可（restic 的 S3 后端认环境变量），但解析结果只往子进程 env 里塞，绝不落日志 |

**不知道什么**：不知道密码管的是哪个仓库、不知道 OSS bucket 是谁——它只认「文件里
KEY=VALUE 的那些行」。

## 解析规则与静默跳过

POSIX 风格分词（复刻 `shlex.split` 的语义）：认 `export ` 前缀、单双引号、反斜杠转义、
空行与 `#` 注释行。**解析失败的行静默跳过**——报错就得说清哪一行坏了，那句话本身就是
泄漏面。

文件不存在返回 `{}` 而不是抛：OSS 开着但凭据还没落地，是新机部署途中的正常中间态。让它
往下走，restic 会以非零码失败，日志里留下标准的 `OSS push FAILED with exit code N` 契约行
——比在这里抛一个不进日志的异常有用得多。

## 提供的接口

| 接口 | 契约 |
| --- | --- |
| `parseOssCredentials(text)` | 文本 → env 表；坏行只跳那一行 |
| `readOssEnv(file)` | 文件不在 / 读不动 → `{}`，绝不抛 |

消费方只有两处：备份管线的 OSS 那几段、`windows-backup.restic` 透传命令的 `repo: "oss"`
那趟——都是「解析结果塞进子进程 env」这一条路。

## 依赖的接口

只依赖 node 内建 `fs`。无注入点——纯函数，喂字符串就能测。

## 怎么单独测

`tests/restic-credentials.test.ts`：喂各种行形（`export `、引号、注释、引号不闭合、
`=` 开头的空键），证明解析结果与静默跳过的边界；喂不存在的路径，证明 `{}`。
