**本页回答**：仓库密码与 OSS AccessKey 各走什么路进 restic、为什么解析失败的行不报错。

`src/credentials.ts`。纪律一句话：**只算路径、只解析 `KEY=VALUE`，不往日志、输出、异常消息里漏一个字节**。凭据也永不进设置——17 个设置键里没有一个是密钥。

## 两份凭据，两种待遇

| 文件（在数据目录的 `credentials/` 下） | 待遇 |
| --- | --- |
| `restic-password.txt` | 内容**永不读进本进程**，只把路径交给 restic 的 `--password-file`。读进内存，就有机会被某条日志或某个异常消息带出去 |
| `oss-credentials.txt` | 非读不可（restic 的 S3 后端从环境变量取 AccessKey），但解析结果只进子进程环境变量，不落任何日志 |

## 解析规则

照 Python `shlex.split` 的分词规则：认 `export ` 前缀、单双引号、反斜杠转义、空行与 `#` 注释行。**解析失败的行只跳过、不报错**——
报错就要说出哪一行坏了，那句话本身就会把凭据带进日志。

文件不存在返回 `{}` 而不是抛：OSS 开着但凭据还没放进来，是新机器部署途中的正常状态。往下走，restic 会以非零码失败，日志里留下标准的
`OSS push FAILED with exit code N` 契约行——比在这里抛一个不进日志的异常有用。

用到解析结果的只有两处：备份管线的 OSS 那几段，与 `windows-backup.restic` 透传命令 `repo: "oss"` 的那一次，都是「塞进子进程环境变量」这一条路
（见 [restic 封装与子进程](/docs/modules/restic#环境变量的边界)）。

## 测试

`tests/restic-credentials.test.ts` 传入各种写法（`export `、引号、注释、引号不闭合、`=` 开头的空键），查解析结果与只跳过坏行的边界；传入不存在的路径，查回 `{}`。
