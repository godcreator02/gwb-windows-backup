插件包 `@godcreator/gwb-windows-backup` 在仓里的 `plugins/windows-backup/`。它只做三件事：

- **每分钟一跳**：定时器每 60 秒醒一次，距上一轮结束满 `frequency-minutes`（默认 30）分钟就跑下一轮
- **跑一轮备份**：把白名单目录备份进本地 restic 仓库；开了 OSS，就对 OSS 上的另一个 restic 仓库**再独立备份一次**；每天第一轮同时按保留窗口删旧快照
- **回答「备份还在正常运行吗」**：上次备份、磁盘余量、快照新鲜度三项，每次问都现算

备份只在工作台运行时进行。怎么装、怎么配、怎么确认它在跑，见[用法](/docs/usage)；包内部怎么分工，见[插件包](/docs/windows-backup)。

## 判据

一句话：**代码只做没人盯着也要一直做的事**——定时备份、给人和 agent 看状态；一次性操作（装 restic、首次配置、USB 离机副本、灾后恢复）是人在现场的事，归手册。由它推出三条：

- **状态和备份本体一样重要**：备份断了三个月没人发现，等于没有备份。所以状态每次现算，一轮失败，下一次问就是黄灯
- **凭据纪律比便利重要**：仓库密码与 OSS 密钥由当前 home 的 secret 槽保管，只注入本次子进程；日志与回执遮掉已知凭据
- **误报比漏报更伤**：告警天天响，人就不看了。时间类判据一律容忍两个周期；判不了的项画灰、不算失败；要人去做的维护单独提醒，不让状态灯变黄

## 刻意不做的事

每条是决定不做，不是排期没排到，理由见轨迹卡[四件刻意不做的事](/trajectory/2026-09-26-not-doing-four)：

- 不做整机镜像：本插件只管 restic 文件级快照
- 不做恢复向导：恢复用 `windows-backup.restic` 透传 `restore`，步骤归手册
- 不做按快照浏览文件：那是 `restic restore` / `restic mount` 的事
- 不自建凭据保险箱：保管与导入交给 gwb-settings，备份插件只负责迁移和使用

另外两条此刻的边界：**工作台没运行就不备份**，这是有意接受的代价；`run` 与 `restic` 两条命令一直等到子进程结束才回执，
**没有作业 id、取消与断线后恢复**——要不要做成作业接口在 [issue #1](https://git.tianshen02.online:28377/godcreator/gwb-windows-backup/issues/1) 里等决定。
