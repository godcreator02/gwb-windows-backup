# gwb-windows-backup 是什么

gwb 内核线上的 Windows 个人备份件：restic 打快照 + 阿里云 OSS 异地副本 + 周期自检 +
一扇窗格，跑在 gwb-kernel（单元 `26090705ymz`）上。定时器每 30 分钟一轮（可配），宿主
不在就不备份、起来 30 秒后补——它是给「这台工作台开着的机器」设计的备份，不是系统级
的灾备服务。

自 DSH 原生件重做（老仓 `D:\dshfiles\26082800ktb\god-windows-backup` 只作参考）：域逻辑
（锁、备份管线、五项健康判据、restic 参数表、日志契约句、凭据纪律）语义照搬、代码重写；
宿主层整个换新线契约——命令总线、设置件、数据件、外壳窗格。

## 判据：代码只装「没 AI 也在」的事

这个件做什么、不做什么，都从一句话推出来：代码只装定时备份、周期自检、观察面这类
**没人盯着也会自己发生**的事；一次性操作——装 restic、首次配置、USB 离机副本、灾后
取数据——是人在现场的事，归手册不归代码。

推论有三条。**其一**，备份的价值在「沉默地转着」，所以观察面（五项健康、窗格、日志契约）
与备份本体同权重——备份断三个月没人发现，等于没有备份。**其二**，凭据纪律比便利重要：
密码只交路径、AccessKey 只进子进程 env，省的那几行代码不值得拿泄漏面换。**其三**，
失败要「响」：健康检查误报比漏报更伤（天天喊狼来了，真出事那次一起被忽略），所以判据
的容忍口径一律给两个周期。

## 与内核的关系

本件是内核线上的一件，不是内核的一部分。硬 peer 四条——commands / settings / data /
plugin-api——是备份的命根，缺哪个这个件都没有意义；shell / shared-react 是浏览器半的
前提，走可选 peer：headless home 里备份照跑。定时器不自己造，走内核认定的开件
`@cordisjs/plugin-timer`，由 home 的 cordis.yml 条目提供——条目缺了本件整个挂起，
宁挂起不静默不备份。
